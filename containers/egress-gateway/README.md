# Egress-gateway песочницы (self-serve)

Прототип сетевого скоупа для self-serve режима (пункт 3 из
[SELF-SERVE-DESIGN.md](../../SELF-SERVE-DESIGN.md) §4). Обеспечивает: запущенный
агент физически не может выйти никуда, кроме доказанной цели и эндпоинта модели.

> **Статус: прототип.** Скрипты отражают модель и nftables-правила из дизайна, но
> требуют валидации на реальном Docker-хосте (нужны root/NET_ADMIN на шлюзе и
> проверка маршрутизации). Не запускалось в этой сессии. Не для продакшена как есть.

## Почему снаружи контейнера

Песочнице выдаются `NET_ADMIN`/`NET_RAW` (нужны инструментам пентеста), значит она
может переписать свои iptables и снять любые правила изнутри. Поэтому ограничение
egress ставится **вне** её сетевого namespace — на отдельном шлюзе-контейнере,
через который проходит весь её трафик.

## Модель

```
[sandbox] --(internal network, без внешнего маршрута)--> [egress-gateway] --(uplink)--> allowlist
   AIRAIDER_SELF_SERVE=1                                   nftables default-deny
   AIRAIDER_DOCKER_SANDBOX_NETWORK=airaider-egress-<scan>  allow: pinned IP:port
```

- Песочница подключается к per-scan сети `airaider-egress-<scan_id>`; её дефолтный
  маршрут — на шлюз. Сама наружу не ходит.
- Шлюз форвардит только на **запиннингованные IP** цели и эндпоинтов модели
  (матч по IP, не по hostname — защита от DNS-rebinding). Остальное — drop.
- Явный drop: облачная метадата `169.254.169.254`, private/loopback/link-local,
  сам хост. Если цель резолвится в приватный IP — сеть не поднимается.

## Использование (со стороны воркера платформы)

```bash
# 1. Поднять per-scan сеть + шлюз с allowlist (цель + эндпоинт модели):
./setup-scan-network.sh <scan_id> \
  staging.example.com:443 \
  api.openai.com:443

# печатает имя сети → передать песочнице:
export AIRAIDER_SELF_SERVE=1
export AIRAIDER_DOCKER_SANDBOX_NETWORK=airaider-egress-<scan_id>
# ... запуск ai-raider ...

# 2. После прогона — снести сеть и шлюз:
./teardown-scan-network.sh <scan_id>
```

При `AIRAIDER_SELF_SERVE=1` `docker_client.py` не прокидывает `host.docker.internal`
и отказывается стартовать, если сеть песочницы не задана (fail-closed).

## Что ещё нужно до продакшена

- Валидация маршрутизации/форвардинга на Docker-хосте, тесты «сандбокс не достучался
  никуда кроме allowlist», в т.ч. попытки поднять свои iptables изнутри.
- Лимиты стоимости/времени и убийство по таймауту (оркестратор).
- Логирование drop-событий как сигнала злоупотребления.
- IPv6-политика (сейчас правила ориентированы на IPv4; при включённом IPv6 в docker
  добавить зеркальные drop-правила).
